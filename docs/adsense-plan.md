# 애드센스 'Low value content' 대응 계획

2026-10-26 구글 애드센스 심사에서 **"가치가 별로 없는 콘텐츠(Low value content)"** 사유로 거절됐다.
구글 안내는 세 가지를 요구한다 — 고유한 가치 제공, 지속적인 콘텐츠 관리, 실제 사용자 관심 유도.

이 문서는 **계획**이고, 어디까지 했는지는 [`adsense-progress.md`](./adsense-progress.md)에 적는다.
다음 세션에서 "이어서 진행"이라고 하면 **두 파일을 먼저 읽고** 이어서 한다.

## 절대 원칙 (모든 단계에 적용)

- **`note`는 한 글자도 바꾸지 않는다.** 화면용 문장은 새 필드 `publicNote`에 **원문 그대로 복사**만 한다.
- 새 조사·추측·고쳐 쓰기·요약 금지. `data/hospitals.json`의 **기존 값 변경 금지**(필드 추가만).
- 애드센스 코드(`app/layout.tsx` `<head>`의 ca-pub-7557818401283330)·`public/ads.txt` 수정 금지.
- `public/악기연주곡(bgm)/`·`검진앱실행.bat` 커밋 금지.
- 개발 서버를 켠 채 `npm run build` 금지. 검증용 서버는 끝나면 반드시 끄고 프로세스·포트를 확인한다.
- push는 사용자가 지시할 때만.

## 단계

### 1단계 — note 본문화 시범 + 작은 개선 (2026-11-03, 완료)

- `lib/noteBody.ts`: note를 **문단 단위**로 표시/숨김/섞임 판정. 통과 문단만 원문 그대로 렌더.
- 시범 10곳에만 적용(`NOTE_BODY_PILOT_IDS`). 내부 링크·`/about` 보강·홈 글 카드.
- 한계: 문단 단위라 "가격표 + 그 가격을 어디서 확인했는지"가 한 문단이면 통째로 보류됐다.
  섞임 2,745문단(47%)·992곳.

### 1.5단계 — publicNote 도입 (오늘)

문단 단위의 한계를 **문장 단위**로 푼다. 다만 note를 고치지 않기 위해 **새 필드**에 원문 문장만 복사한다.

- `publicNote`: note의 방문자용 문장만 **글자 그대로** 복사. 순서·문단 유지.
- 제외 문장: ① 정보와 내부 메모가 한 문장에 섞인 것 ② 혼자 읽어 뜻이 통하지 않는 것(괄호로 시작, 앞 문장을 가리키는 것)
  ③ 조사 과정·분류 표현("~에 해당한다", "어디에도", "N갈래", "확인했다", CSV, 명단, 필드, 규칙 …)
  ④ 화면 표(검진비용·결과통보·소요시간·식사·주차·교통)와 같은 내용을 반복하는 것
- 국가검진 지정 상자는 note 원문 대신 **정해진 문장**으로 쓴다.
  지정: `국가건강검진 지정기관입니다: <범위> (국민건강보험공단 명단 YYYY-MM-DD 확인)` /
  미지정: `국민건강보험공단 검진기관 명단(YYYY-MM-DD 확인)에서 확인되지 않습니다`.
  범위가 확실하지 않으면 범위 없이. "공식 확인 필요"·CSV·순번·정확 일치·명단 N건 같은 표현은 노출 금지.
- 검증: publicNote의 **모든 문장이 note에 글자 그대로 존재**(불일치 0건), **note 0바이트 변경**, 문장 분리 오류 점검.
- 함께: 상세 페이지가 브라우저로 보내는 데이터에서 note 원문 제거, 검진 안내 글에 `publishedAt`/`updatedAt`,
  조사 규칙(`brief.md`·`README.md`)에 publicNote 작성 규칙 추가.

### 2단계 — publicNote 전체 적용

- 1,036곳 전체에 publicNote 생성. **무작위 20곳 렌더 확인.**
- 색인 기준(`isIndexable`)에 화면 고유 본문 글자수를 넣을지 검토 — **색인 장수가 줄지 않는 경우에만** 적용한다.

### 3단계 — 콘텐츠 (2~3주)

- push할 때마다 검진 안내 글 **2~3편 추가**(총 12~20편). 공식 자료만 근거, **출처·확인일 명시**,
  한 편 **2,000자 이상**, 의사 상담 안내 포함.
- 시·도 16곳에 **그 지역 데이터 기반 해설 3~5문장**(병원 수·등급 구성·지정 비율 등 이미 가진 값으로).

### push 규칙

- **최소 2일 간격.** push 전 개발 서버를 끈 상태에서 `npm run build` 통과 확인. push 후 라이브 반영 확인.

### 재신청 전 최종 점검

- 2026-11-03 현황 점검과 같은 항목으로 **전/후 비교표**를 만들고 재신청 가능 여부를 판단한다.
- **재신청 버튼은 사용자가 누른다.**
