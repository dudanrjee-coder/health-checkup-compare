# 전국 건강검진 예약 비교 (초기 버전)

Next.js(App Router) + TypeScript + Tailwind CSS로 만든 정적 데이터 기반 건강검진 예약 비교 웹앱입니다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:3000 접속.

## 구조

- `types/hospital.ts` — `Sido`, `Tier`, `Hospital` 타입 정의(`Category`는 [28번 항목](#28-category-필드-폐지--tier-단일-분류로-전환-2026-08-22)에서 폐지). `SIDO_LIST` / `TIER_LIST` 배열에서 타입을 파생시켜, UI에 표시되는 전체 목록과 타입이 항상 일치하도록 구성했습니다. `Hospital.verifiedAt`은 `phone`/`reservationMethod`/`note`를 실제로 확인한 날짜입니다.
- `data/hospitals.json` — 데이터(16개 시/도 전 지역, 153곳 — 상급종합병원 37곳 + 종합병원 116곳). 각 항목은 아래 [데이터 입력 규칙](#데이터-입력-규칙-병원-등급-무관-공통-규칙)에 따라 홈페이지에서 직접 확인한 값입니다.
- `lib/hospitals.ts` — JSON 데이터 로드 및 필터링 헬퍼. `filterHospitals(null, ...)`은 지역 제한 없이 전국 목록을 돌려줍니다.
- `lib/regions.ts` — 전국 초기 뷰(`NATIONWIDE_VIEW`)와 시/도별 지도 기준점(`SIDO_VIEW`). 좌표가 등록된 병원이 없는 지역을 골랐을 때 지도를 옮길 위치로 씁니다.
- `components/SidoSelect.tsx` — 시/도 드롭다운(16개 전체 표시, 데이터 없는 지역은 "준비 중" 표기).
- `components/TierFilter.tsx` — 등급 필터(4단계 전체 표시, 데이터 없는 등급은 비활성화).
- `components/HospitalCard.tsx` — 병원 카드 UI. 기본은 접힌 상태(이름·배지·지역·전화·예약 방식 한 줄)이고, "펼쳐보기 ▾"로 상세 정보를 연다. 자세한 규칙은 [카드 접기/펼치기](#12-카드-접기펼치기-2026-08-19) 참고.
- `components/SearchBox.tsx` — 병원명·지역 통합 검색창. 마우스 환경에서는 화면 키보드 아이콘(⌨)이 함께 나온다.
- `components/HangulKeyboard.tsx` — 두벌식 화면 키보드. 한글 조합은 `hangul-js`의 `disassemble`/`assemble`로 처리한다.
- `lib/useHoverCapable.ts` — 마우스 환경 여부 판별 훅(지도 호버 팝업과 화면 키보드가 함께 쓴다).
- `components/HospitalMap.tsx` — Leaflet + OpenStreetMap 지도(마커·팝업·선택 연동). Leaflet이 `window`에 의존하므로 `app/page.tsx`에서 `next/dynamic`의 `ssr: false`로 불러옵니다.
- `scripts/geocode.mjs` — Nominatim으로 병원 좌표를 조회해 `hospitals.json`에 `lat`/`lng`로 캐싱하는 스크립트.
- `app/page.tsx` — 메인 페이지(상태 관리 및 화면 조합, 리스트/지도 좌우 분할 레이아웃).

## 현재 범위

- 백엔드 서버 없이 정적 JSON 데이터만 사용합니다.
- 크롤링, 로그인, 결제, 실시간 예약 연동은 포함하지 않습니다.
- 16개 시/도 전 지역에 데이터가 등록되어 있습니다(상급종합병원·종합병원급 중심). "준비 중" 안내는 향후 새 지역을 추가할 때를 위한 처리이며, 현재는 표시되지 않습니다.
- 페이지에 처음 들어오면 지역을 고르지 않아도 **전국 지도(중심 36.5/127.8, 줌 7)와 전국 병원 목록**이 바로 보입니다. 시/도를 고르면 지도가 해당 지역으로 이동·확대되고 목록도 그 지역으로 좁혀집니다.
- 지도에는 `lat`/`lng`가 채워진 병원만 마커로 나옵니다. **2026-08-23 기준 153곳 중 144곳에 좌표가 채워져 있습니다.** 창원파티마병원·근로복지공단 대전병원·드림종합병원·곽병원·천주성삼병원·인천백병원·인천세종병원·첨단종합병원·KS병원은 OSM에 병원 노드가 없거나 동명 기관에 잘못 매칭되어 비워 두었고(사유는 17·18·22·23·24·25번 항목), 아홉 곳은 카드에만 나오고 지도 마커로는 표시되지 않습니다.
- `address`는 153곳 전부 채워져 있습니다. 상세 정보 필드(`priceRange` 등)는 홈페이지에 실제로 공지된 것만 넣으므로 병원마다 채워진 개수가 다릅니다.

## 데이터 추가 방법

`data/hospitals.json`에 `Hospital` 타입에 맞는 객체를 추가하면 자동으로 화면에 반영됩니다. `region.sido`와 `tier` 값은 `types/hospital.ts`의 `SIDO_LIST` / `TIER_LIST`에 정의된 값만 허용됩니다.

> **`category` 필드는 2026-08-22에 폐지되었습니다. 신규 병원을 등록할 때 `category`를 채우지 마세요.** 병원 분류는 보건복지부가 공식 지정하는 `tier`(상급종합병원/종합병원/병원/의원) 하나로만 합니다. 폐지 사유는 [28번 항목](#28-category-필드-폐지--tier-단일-분류로-전환-2026-08-22) 참고.

**신규 병원 등록 절차(실제로 써 온 순서).** 항목을 만들어 주는 전용 스크립트는 없고 `data/hospitals.json`을 직접 편집합니다. 저장소에 있는 스크립트는 `add-national-screening.mjs`(국가검진 문구·값 정규화)와 `geocode.mjs`(좌표 조회) 둘뿐입니다.

1. **조사** — 아래 [데이터 입력 규칙](#데이터-입력-규칙-병원-등급-무관-공통-규칙) 1~8번대로 홈페이지에서 값을 확인한다.
2. **`data/hospitals.json` 직접 편집** — `Hospital` 객체를 추가한다. 이때 `nationalScreeningDesignated`와 국가검진 문구는 넣지 않는다(3번이 붙인다).
3. **`scripts/add-national-screening.mjs`의 `DESIGNATED_SENTENCE_BY_ID`(또는 `NOT_DESIGNATED` / `UNDETERMINED`)에 병원 id와 문구를 등록** — 문구는 반드시 제거 패턴이 아는 시작 단어(`명단에는` / `명단에 있는` / `공식 홈페이지` / `최초 등록 시` / `법인명` / `정부가`)로 시작하고, 문장 안에 마침표를 넣지 않는다.
4. **`node scripts/add-national-screening.mjs` 실행** — 2번과 3번을 건너뛰고 먼저 돌리면 일반 문구가 임시로 붙었다가 나중에 교체되어 "문장 소실"로 잘못 잡힌다([22번 항목](#22-대구울산-전수-조사-2026-08-20) 참고).
5. **`scripts/geocode.mjs`의 `QUERIES`에 조회어 추가 후 `node scripts/geocode.mjs` 실행** — 좌표가 도로·버스정류장으로 잘못 잡히면 조회어를 고치고, 그래도 안 되면 `QUERIES`에서 빼고 좌표를 비운다.
6. **좌표·note를 직접 손댔다면 `add-national-screening.mjs`를 한 번 더 돌려 문구를 note 맨 뒤로 정규화**한 뒤 [15번 항목](#15-csv-2차-대조와-동명-기관-문제-2026-08-19)의 세 가지로 멱등성을 검증한다.
7. **`npx tsc --noEmit`으로 타입 검사** — 개발 서버를 켠 채 `npm run build`는 돌리지 않는다([14번 항목](#14-csv-대조로-확정한-국가검진-지정-여부-2026-08-19)).

## 지도 좌표(lat/lng) 채우는 방법

지도에 표시하려면 `lat`/`lng`가 있어야 합니다. 좌표는 아래 스크립트로 한 번만 조회해서 JSON에 캐싱하며, 페이지를 열 때마다 API를 호출하지 않습니다.

```bash
node scripts/geocode.mjs
```

- 조회할 주소는 `scripts/geocode.mjs`의 `QUERIES`에 `병원 id: "주소"` 형태로 추가합니다. 값은 후보 배열도 가능하며 앞에서부터 시도합니다.
- Nominatim 이용 정책에 맞춰 요청 사이에 1.1초 간격을 두고 `User-Agent`를 보냅니다.
- **이미 `lat`/`lng`가 있는 병원은 건너뜁니다.** 새로 추가한 병원만 조회하므로 스크립트를 다시 돌려도 안전합니다. 전부 다시 받으려면 `--force`를 붙입니다.
- 결과 좌표가 해당 시/도 범위를 벗어나면 잘못 매칭된 것으로 보고 저장하지 않습니다(엉뚱한 동명 지역이 잡히는 것을 막기 위함).
- 도로명 주소만으로는 건물이 아니라 도로 전체가 잡히는 경우가 있습니다. 그럴 때는 정식 병원명을 첫 후보로 넣습니다.
- 좌표가 없는 병원은 카드에는 나오지만 지도에는 표시되지 않고, 해당 지역 지도 자리에는 안내 문구가 뜹니다.

## 데이터 입력 규칙 (병원 등급 무관 공통 규칙)

대학병원뿐 아니라 종합병원/병원/의원급을 추가할 때도 아래 규칙을 항상 동일하게 적용합니다. 각 항목은 실제로 병원 홈페이지 등에서 확인한 값만 입력하고, 추측이나 오래된 정보를 그대로 옮기지 않습니다.

### 1. 조사 순서

1. 병원 공식 홈페이지를 검색으로 찾는다.
2. 홈페이지 내 "건강검진센터 / 종합검진센터 / 건강증진센터" 안내 페이지에서 예약 관련 정보를 확인한다.
3. 없으면 "예약안내 / 진료예약 / 전화번호 안내" 등 병원 대표 예약 페이지를 확인한다.

### 2. `phone` 값 결정 (우선순위)

| 순위 | 조건 | 처리 |
| --- | --- | --- |
| 1순위 | 검진센터 전용 예약 전화번호가 확인되는 경우 | 그 번호를 `phone`에 사용 |
| 2순위 | 전용 번호가 없고(동네 의원급 등 검진센터가 별도로 없는 경우 포함) 대표 전화번호만 확인되는 경우 | 대표 전화번호를 `phone`에 사용하고, `note`에 반드시 `"대표번호(검진 전용 번호 없음)"`라고 표시 |
| 3순위 | 검색해도 대표번호조차 확실히 확인되지 않는 경우 | `phone`을 빈 문자열(`""`)로 두고, `note`에 `"확인 필요"`라고 표시 |

- 전용 번호가 여러 개(예: 종합검진센터/일반검진센터)로 나뉘어 있으면, 가장 포괄적인 검진센터(대개 "종합검진센터")의 번호를 `phone`에 쓰고, 나머지는 `note`에 부연 설명한다.
- ARS로 대표번호에서 검진 부서로 연결되는 경우(예: "대표번호 → 2번 → 3번")는 전용 번호가 아니라 **대표번호(2순위)** 로 취급하고, `note`에 ARS 경로를 함께 적는다.

### 3. `reservationMethod`, `note`, `sourceUrl`

- `reservationMethod`는 확인된 예약 채널(전화/인터넷/방문 등)을 실제 안내 문구 기준으로 구체적으로 적는다. 전화번호가 있다면 괄호로 함께 표기한다. 예: `"전화 예약(042-000-0000, 평일 09:00~16:00) / 인터넷 예약(홈페이지 종합검진예약)"`
- `note`는 위 우선순위 표시(`"대표번호(검진 전용 번호 없음)"`, `"확인 필요"`) 외에도 완전예약제 여부, 운영시간, 전용번호가 여러 개인 경우의 구분 등 참고할 만한 부가 정보를 적는다.
- `sourceUrl`은 실제로 확인한 그 페이지의 URL(홈페이지 최상단이 아니라 검진센터/예약안내 상세 페이지)을 넣는다.

### 4. `verifiedAt`

- `phone` / `reservationMethod` / `note`를 확인한 날짜를 `YYYY-MM-DD` 형식으로 반드시 채운다.
- 이후 재검증 시 이 날짜를 갱신한다. 오래된 `verifiedAt`은 정보가 바뀌었을 수 있다는 신호로 취급하고, 주기적으로 재확인한다.
- 아래 5번 항목(상세 정보 필드)을 새로 채우거나 갱신할 때도 `verifiedAt`을 함께 갱신한다.

### 5. 상세 정보 필드 (`priceRange`, `waitingPeriod`, `accessInfo`, `duration`, `resultNotice`, `mealProvided`)

모두 optional 필드이며, **해당 병원의 건강검진센터 홈페이지에 실제로 공지된 정보만** 사용한다. 추정하거나 다른 병원 사례로 유추해서 채우지 않는다.

| 필드 | 내용 | 작성 기준 |
| --- | --- | --- |
| `priceRange` | 검진 가격대 | 홈페이지에 게시된 프로그램별 가격을 요약. 예: `"기본검진 33만원 ~ 프리미엄 253만원"`. 성별로 가격이 다르면 함께 표기 |
| `waitingPeriod` | 예약 대기 기간 | **아래 별도 주의사항 참고** |
| `accessInfo` | 주차/대중교통 접근성 | 가까운 지하철역·도보 시간, 주요 버스 노선, 주차 무료 시간/요금 등을 "오시는 길"·"주차안내" 페이지 기준으로 기재 |
| `duration` | 검진 소요시간 | 홈페이지의 "검진절차안내" 등에 명시된 소요시간을 그대로 기재. 선택검사에 따라 달라지면 그 취지도 함께 적는다 |
| `resultNotice` | 결과 통보 방식 | 우편/온라인조회/카카오톡/방문상담 등 실제 안내된 통보 채널을 나열 |
| `mealProvided` | 검진 후 식사 제공 여부 | `"제공(빵/우유 등 간단식)"` 또는 `"미제공"` 형태로 기재. 개인검진 절차 안내에 명시된 경우에만 채우고, 기업(단체)검진 등 다른 프로그램에만 해당하는 안내는 개인검진에 그대로 적용하지 않는다 |

### 6. `address` (상세주소)

- 병원 공식 페이지(오시는 길·푸터 등)에 적힌 주소를 **그대로** 옮긴다. 공식 페이지에 지번·동이 함께 적혀 있으면 포함하고, 도로명만 있으면 도로명까지만 적는다. **동 이름을 임의로 추정해서 붙이지 않는다.**
- 검색 대상에 포함되며(`lib/hospitals.ts`), `scripts/geocode.mjs`의 좌표 조회 입력으로도 쓴다.

#### 주소 동 단위 보강 원칙

공식 페이지에 도로명만 있어 동을 알 수 없을 때는, `scripts/geocode.mjs` 실행 결과(Nominatim/OpenStreetMap의 `display_name`)에서 확인된 동을 덧붙일 수 있다. 단 **어디까지가 병원 공식 정보이고 어디부터가 지도 서비스에서 확인한 정보인지 구분되게** 적는다.

- 형식: `"<공식 주소> (OSM 확인: <동 이름>)"`
  - 예: `"부산광역시 부산진구 복지로 75 (OSM 확인: 개금2동)"`
- 공식 주소 부분은 **고치지 않고 그대로** 두고, 괄호만 덧붙인다.
- 괄호 안 동 이름도 검색 대상에 포함되므로 동 이름으로도 병원을 찾을 수 있다.
- **공식 페이지에 이미 동·지번이 있으면 OSM 값을 덧붙이지 않는다.** 둘이 다를 경우 공식 표기를 따르고, 불일치 사실은 `note`에 적는다. (예: 고려대학교 안암병원 — 공식 지번은 안암동5가, OSM 매칭은 안암동2가)
- OSM은 공식 출처가 아니므로 이 괄호 표기를 근거로 다른 필드(`accessInfo` 등)를 채우지 않는다.

### 7. `nationalScreeningDesignated` (국가검진 지정기관 여부)

**등급으로 추정하지 않는다. 반드시 명단으로 확인한다.**

- 판단 근거는 둘 중 하나여야 한다.
  1. 국민건강보험공단 검진기관 명단(공공데이터 "검진기관검진유형내역" 등)에 해당 병원이 있는지 대조
  2. 병원 공식 홈페이지의 공지(예: "공단건강검진을 시행하지 않습니다")
- "상급종합병원이니까 당연히 지정기관일 것" 같은 추정은 금지한다. 실제로 이 추정 때문에 오류가 났다(아래 정정 내역 참고).

| 값 | 의미 | 카드 배지 |
| --- | --- | --- |
| `true` | 명단에서 확인됨 | 초록색 "국가검진 지정기관" |
| `false` | 명단에 없음이 확인됨 | 주황색 "국가검진 미지정" |
| 없음(`undefined`) | 아직 확인 못 함 | 배지 없음 |

- `note`에는 확인 방법과 시점을 함께 남긴다.
  - 지정: `"국가건강검진 지정기관(국민건강보험공단 검진기관 명단 확인, 2026-08-18 기준). 정부가 상급종합병원의 국가검진 참여 범위를 중장기 검토 중이라 향후 변경될 수 있음."`
  - 미지정(공식 공지로 확인): `"2021년부터 공단(국가)건강검진 미시행, 개인검진만 운영 (공식 확인, 2026-08-18 기준)."`
  - 미지정(명단에만 없음): `"CSV 명단에 없어 국가검진 미지정 가능성 있음, 공식 확인 필요."` — 명단에 없다는 사실만으로 단정하지 말고 이렇게 여지를 남긴다.
- 값을 일괄로 채우거나 고칠 때는 `node scripts/add-national-screening.mjs`를 돌린다(기존 국가검진 문구를 걷어내고 다시 붙이므로 반복 실행해도 안전).

#### 명단이 동명 기관으로 애매할 때 (판단 기준, 참고용)

CSV 명단에 이름은 있는데 **그 항목이 우리가 등록하려는 그 병원인지 특정할 수 없는 경우**가 있다. 명단에 주소 컬럼이 없고 짧고 흔한 이름일수록 그렇다.

**CSV 매칭 실패가 홈페이지 근거를 자동으로 무효화하지는 않는다.** 위 "근거 둘 중 하나" 원칙은 그대로다. 다만 두 근거가 엇갈릴 때 어느 쪽으로 기울일지는 아래를 참고해 판단한다.

| 상황 | 판단 |
| --- | --- |
| 명단 표기가 **법인명이나 주소로 교차 확인**됨 | 지정(`true`) 유지 |
| 교차 확인이 안 되고, 홈페이지 근거도 **일반적인 수준**(국가검진 안내 페이지가 있는 정도) | **미확인**(값 비움)으로 내린다 |
| 교차 확인은 안 되지만 홈페이지 근거가 **구체적**(검진센터와 별도로 운영되는 국가검진 전용 예약번호, 공단 로고·지정기관 표기 등) | CSV가 애매해도 지정(`true`) 유지 가능 |

- 어느 쪽으로 판단하든 **근거와 애매한 이유를 `note`에 남긴다.** 나중에 다시 볼 사람이 같은 조사를 반복하지 않게 한다.
- 미확인으로 내릴 때도 홈페이지에서 확인된 사실은 지우지 말고 함께 적는다(시행 자체는 확인됐지만 명단 특정이 안 된다는 식으로).

**참고 사례 — 나은병원(인천, 2026-08-19):** 명단에 `나은병원`이 법인명 없이 단독으로 있었으나 서울나은병원·국제나은병원 등 동명 기관이 여럿이고 대조에 쓴 CSV에 주소 컬럼이 없어 교차 확인이 불가능했다. 홈페이지 근거도 국가검진프로그램 안내 페이지가 있는 **일반적인 수준**이어서 위 표의 두 번째 줄에 해당한다고 보고 **미확인으로 내렸다.** 반대로 같은 날 확정한 좋은삼선병원·동강병원·엔케이세종병원은 명단 표기에 법인명(은성의료재단·동강의료재단·영제의료재단)이 붙어 있어 첫 번째 줄에 해당했다.

### 8. 온라인 예약 필드 (`bookingUrl`, `bookingType`)

- `bookingUrl`은 **실제로 접속해 본** 예약 페이지의 정확한 URL만 넣는다. 추측한 주소는 넣지 않는다.
- `bookingType`은 그 페이지를 직접 열어 **입력 항목으로 판별**한다.
  - `"자율예약"` — 달력에서 날짜·시간을 직접 골라 그 자리에서 예약이 확정되는 방식
  - `"예약신청"` — 이름·연락처 정도만 남기면 상담원이 나중에 전화로 확정해 주는 콜백형
- **페이지 이름에 속지 않는다.** "온라인 예약", "실시간 예약"이라고 적혀 있어도 실제 입력 항목이 이름·연락처뿐이거나 "담당자가 전화로 확정" 안내가 있으면 `"예약신청"`이다.
- 로그인해야만 볼 수 있는 회원 전용 예약은 확인할 수 없으므로 기준으로 삼지 않는다. 로그인 없이 누구나 쓸 수 있는 경로를 기준으로 적고, 확인하지 못한 회원 경로가 따로 있다면 `note`에 남긴다.
- 온라인 예약 경로가 아예 없거나 확인되지 않으면 두 필드를 모두 비우고, `note`에 `"온라인 예약 불가, 전화예약만 가능"`이라고 적는다.
- **병원이 "홈페이지·모바일 예약 중단" 등 온라인 예약 중단을 공지한 경우, 신청 폼이 기술적으로 아직 열려 있어도 두 필드를 비운다.** 병원이 공식적으로 닫은 경로를 사용자에게 안내하지 않기 위해서다. 이때 `note`에는 `"온라인 예약 중단 공지, 전화예약만 가능"`이라고 적고, `reservationMethod`도 전화 예약만 남긴다. (예: 가톨릭대 대전성모병원)
- 화면에는 `bookingUrl`이 있을 때만 "온라인 예약하기" 버튼이 나오고, `bookingType`이 `"예약신청"`이면 버튼 옆에 `(상담원 콜백)`이 함께 표시된다.

**`waitingPeriod` 작성 시 반드시 지킬 것:**
- 예약 대기 기간은 성수기·비수기, 요일, 프로그램 종류에 따라 수시로 바뀐다. 특정 날짜나 "O월 O일부터 가능" 같은 단정적 표현을 쓰지 않는다.
- 병원 홈페이지의 공지사항이나 안내 문구에 범위 형태(예: "약 1~2개월 소요")로 명시된 경우에만 그 범위를 그대로 기재한다.
- 공식 홈페이지에 게시된 근거를 찾지 못하면(블로그 후기 등 비공식 출처만 있는 경우 포함) **빈 문자열로 남기고 재확인하지 않는다.** 대신 4번 규칙에 따라 `verifiedAt`은 조사를 시도한 날짜로 갱신한다.

**공통: 확인 안 되는 필드 처리**
- 검색해도 확인되지 않는 필드는 값을 비워두고(`""` 또는 필드 자체 생략), `note`에 `"OOO 정보 확인 필요"` 형태로 추가한다(예: `"검진 소요시간 정보 확인 필요"`). 여러 필드가 비어 있으면 각각 따로 적는다.
- 화면(`HospitalCard`)은 빈 값인 필드는 아예 표시하지 않으므로, 데이터에 빈 문자열을 넣어도 UI가 깨지지 않는다.

### 9. 행정구역 개편 반영 원칙 (`region.sido`)

**행정구역 통합·개편은 실제로 법이 시행되어 확정된 것만 반영한다. 추진 중이거나 무산된 통합은 반영하지 않는다.**

시/도 체계(`SIDO_LIST`)는 데이터 전체가 매달린 타입의 뿌리라, 확정되지 않은 개편을 미리 넣으면 존재하지 않는 지역이 드롭다운에 뜨고 이후 되돌리기도 어렵다. 그래서 반영 기준을 다음 하나로 못 박는다.

- **반영 기준**: 관련 법률이 **공포·시행**되어 통합 지자체가 실제로 출범했는가. 뉴스의 "추진", "합의", "논의", "특별법 발의" 단계는 반영하지 않는다.
- 판단은 시/도 공식 홈페이지 표기, 통합 지자체 출범·단체장 선출 사실 등으로 확인한다.
- **시/도만 바뀌고 시/군/구는 그대로인 경우가 대부분이므로 `region.sigungu`는 손대지 않는다.**
- 병원 `address`는 6번 규칙대로 **공식 페이지 표기를 그대로** 옮긴다. 병원이 아직 옛 주소를 쓰고 있으면 `region.sido`만 새 체계로 맞추고 `address`는 건드리지 않으며, 그 사실을 `note`에 남긴다.
- `SIDO_LIST`를 고치면 `lib/regions.ts`의 `SIDO_VIEW`(`Record<Sido, MapView>`)와 `scripts/geocode.mjs`의 `SIDO_BOUNDS`도 함께 고쳐야 한다. 앞은 타입 에러로 걸리지만 `SIDO_BOUNDS`는 평범한 객체라 안 걸리니 직접 확인한다.
- **OSM/Nominatim의 개편 반영 시점은 따로 확인한다.** 이번 광주·전남 건은 Nominatim이 새 이름과 옛 이름을 모두 인식했다(2026-08-19 확인). `scripts/geocode.mjs`의 `QUERIES` 주소 문자열은 좌표 조회용 입력일 뿐 우리 데이터 모델과 별개이므로, 이미 좌표가 캐싱된 항목은 옛 표기라도 굳이 고치지 않는다. 새 이름으로 조회가 안 되는 지역이 나오면 옛 이름을 쓴다.

### 11. 지역명 자동 전환과 한글 IME (2026-08-19)

검색어가 시/도 이름 하나로만 좁혀지면(`findUniqueSidoMatch`) 드롭다운을 그 지역으로 바꾸고 검색창을 비운다. 이때 **한글 IME의 조합(composition) 상태를 반드시 먼저 확정시켜야 한다.**

- "대전"을 한글 IME로 치면 마지막 글자 `전`이 아직 조합 중이다. 200ms 디바운스가 그 조합 도중에 터진다.
- 조합 중에 `setSearchInput("")`으로 값만 비우면, IME가 조합 버퍼의 글자를 다시 밀어넣어 **검색창에 글자가 그대로 남는다.**
- 그래서 `app/page.tsx`의 자동 매칭 effect는 값을 비우기 **전에** 입력창에 `blur()`를 걸어 조합을 확정시키고, 비운 뒤에 포커스를 되돌려준다. `components/SearchBox.tsx`가 `inputRef`를 받는 이유가 이것이다.

**포커스 복원에 `requestAnimationFrame`을 쓰지 않는다.** 프레임이 그려지지 않는 환경(비활성 탭, 숨겨진 창)에서는 rAF 콜백이 돌지 않아 포커스가 영영 돌아오지 않는다. `HospitalMap`이 `fadeAnimation`을 끈 것과 같은 이유이며, `setTimeout`을 쓴다.

#### 이 동작을 브라우저 자동화로 검증할 때 주의

- **자동화 입력에는 IME 조합 상태가 없다.** 값만 바꿔 넣는 방식으로는 이 버그가 재현되지 않으므로, 자동화가 통과했다고 IME 환경에서도 된다고 단정하면 안 된다.
- **창이 숨겨져 있으면 브라우저가 타이머를 1초 이상으로 스로틀링한다.** 200ms 디바운스가 제때 안 터져 결과가 한 박자씩 밀리고, 멀쩡한 코드가 깨진 것처럼 보인다. 실제로 이 때문에 "고친 코드가 기능을 깨뜨렸다"고 잘못 판단한 적이 있다. 검증 시 각 단계에 **2.5초 이상** 여유를 준다.

### 12. 카드 접기/펼치기 (2026-08-19)

34곳 모두 상세 필드가 채워지면서 카드가 너무 길어져, `HospitalCard`를 **기본 접힘 + 펼쳐보기** 구조로 바꿨다.

| 상태 | 보이는 것 |
| --- | --- |
| 접힘(기본) | **1줄** 병원명 + tier·category·국가검진 배지 / **2줄** "지역 · 전화(tel 링크)" / **3줄** 예약 방식 한 줄 요약 / 우측 하단 "펼쳐보기 ▾" |
| 펼침 | 위 항목 + `affiliation`(소속), `priceRange`·`duration`·`waitingPeriod`·`resultNotice`·`mealProvided`·`accessInfo`, 온라인 예약 버튼, 주변 맛집 링크, `note`, 출처 링크, `verifiedAt`. 버튼은 "닫기 ▴"로 바뀐다 |

- **값이 빈 필드는 펼친 상태에서도 계속 숨긴다.** 기존 `DETAIL_FIELDS.filter` 동작 그대로다.
- 펼침 상태는 카드마다 `useState`로 따로 들고 있어 서로 간섭하지 않는다.
- 높이 애니메이션은 `grid-template-rows: 0fr → 1fr` + `overflow-hidden`으로 준다. 내용 높이를 미리 재지 않아도 되고 카드 길이가 제각각이어도 동작한다.
- **펼쳐보기 버튼은 `event.stopPropagation()`으로 카드의 `onSelect`(지도 이동) 전파를 끊는다.** 버튼을 눌렀을 때 지도가 함께 움직이면 안 된다.
- 접힌 동안 안쪽 링크·버튼이 키보드 탭 순서에 남지 않도록 `visibility`를 함께 쓴다. 접을 때는 `delay-300`으로 높이 애니메이션이 끝나는 시점에 맞춰 숨긴다(먼저 숨기면 내용이 뚝 끊긴다). **React 18은 boolean `inert`를 그대로 넘기지 못하므로 `inert`는 쓰지 않는다.**

#### 헤더 레이아웃 (모바일)

작업 중 발견한 **기존 버그**도 함께 고쳤다. 배지 묶음에 `shrink-0`가 걸려 있어 375px 폭에서 병원명 칸이 1px까지 짓눌리고 이름이 한 글자씩 세로로 쪼개졌다(헤더 한 개가 458px).

- 헤더를 `flex-wrap`으로 두고, 병원명 칸에 `basis-full sm:flex-1 sm:basis-auto`를 줘서 좁은 화면에서는 이름이 한 줄을 다 쓰고 배지가 아랫줄로 내려가게 했다.
- `flex-1 min-w-0`만으로는 부족하다. 줄바꿈 대신 0까지 축소되는 쪽이 먼저 일어나기 때문이다.
- 결과: 모바일 헤더 458px → 82px, 목록 총높이 24,716px → 9,520px. 데스크톱 배치(이름 왼쪽·배지 오른쪽)는 그대로다.

#### `add-national-screening.mjs`에서 고친 결함 3건

이 스크립트는 "국가검진 문구를 걷어내고 다시 붙이므로 반복 실행해도 안전하다"는 것이 계약인데, 실제로 돌려 보니 **데이터를 손상시키고 있었다.** 값을 갱신하면서 함께 고쳤다.

1. **문장이 중복 삽입됐다.** 미지정 문구를 걷어내는 패턴이 `"...공식 확인 필요."`만 잡고, 뒤에 괄호 부연이 붙은 변형(`"...공식 확인 필요(2026-08-18 재확인 ...)."`)은 못 잡았다. 그래서 기존 문장이 남은 채 새 문장이 덧붙었다. 패턴에 `(\([^)]*\))?`를 넣어 해결.
2. **note 뒷부분이 통째로 지워졌다.** 새로 추가한 문구를 걷어내려고 쓴 패턴의 `[\s\S]*$`가 너무 탐욕적이어서, 뒤에 있던 무관한 문장(대전한국병원의 "포괄2차 종합병원 지원사업 지정" 근거)까지 삼켰다. 뒤따르는 부연 문장까지만 지우도록 범위를 좁혀 해결.
3. **개별 근거가 일반 문구로 덮였다.** 강원대학교병원은 명단 외에 홈페이지 공지("국민건강보험 검진기관" 명시)까지 근거로 적어 뒀는데, 모든 지정기관에 같은 문구를 붙이는 구조라 그 근거가 사라졌다. `DESIGNATED_SENTENCE_BY_ID`로 병원별 문구를 지정할 수 있게 바꿔 해결.

고친 뒤 **연속 2회 실행해 결과가 완전히 같은 것(멱등성)과, 실행 전후로 note 내용이 사라지지 않는 것**을 확인했다.

#### 개발 서버를 켠 채 `npm run build`를 돌리지 말 것

같은 `.next` 디렉터리를 쓰기 때문에, 개발 서버가 도는 중에 프로덕션 빌드를 하면 dev 청크(`main-app.js`, `app-pages-internals.js`, `layout.css`)가 덮여 **404가 나고 화면이 아무 반응도 하지 않는다.** 데이터나 코드 문제로 착각하기 쉽다. 증상이 보이면 개발 서버를 멈추고 `.next`를 지운 뒤 다시 띄운다.

#### 동명 기관은 이름만으로 확정하지 않는다

나은병원은 명단에 `나은병원`이 법인명 없이 단독으로 올라 있으나, **서울나은병원·국제나은병원 등 동명 기관이 여럿이고 대조에 쓴 CSV에 주소 컬럼이 없어** 그 항목이 인천 나은병원인지 특정할 수 없다. 홈페이지 근거도 국가검진프로그램 안내 페이지가 있는 일반적인 수준이어서, 7번 규칙의 판단 기준상 **미확인**에 해당한다고 보고 값을 비워 배지를 띄우지 않는다(`note`에 경위와 "병원 직접 문의 권장"을 남겼다). **CSV 매칭 실패 자체가 홈페이지 근거를 무효화해서가 아니다.**

- **법인명이 붙은 표기가 오히려 안전하다.** 좋은삼선·동강·엔케이세종은 명단 표기에 법인명이 함께 있어 우리가 확인한 운영 주체(은성의료재단·동강의료재단·영제의료재단)와 대조할 수 있었다. 반대로 짧고 흔한 이름은 동명 위험이 크다.
- 이름으로만 매칭될 때 어떻게 판단할지는 7번 규칙의 [명단이 동명 기관으로 애매할 때](#명단이-동명-기관으로-애매할-때-판단-기준-참고용) 표를 따른다. 교차 확인이 안 된다고 **무조건** 값을 내리는 것은 아니다 — 홈페이지 근거가 구체적이면 지정 상태를 유지할 수 있다.

#### 스크립트에 "미확인" 범주를 추가했다

`add-national-screening.mjs`는 원래 지정(`true`)과 미지정(`false`) 두 갈래뿐이라, 다시 돌리면 나은병원을 자동으로 `true`로 되돌려 버린다. `UNDETERMINED` 맵을 추가해 **값을 아예 넣지 않는(undefined) 세 번째 갈래**를 만들었다.

- `true`(지정) / `false`(명단에 없음이 확인됨) / **없음(아직 모름)** 은 서로 다른 상태다. 배지도 각각 초록·주황·없음으로 다르게 나온다.
- 실행 요약도 `지정 41곳 / 미지정 2곳 / 미확인 1곳`으로 세 갈래를 모두 보여준다.
- 고친 뒤 연속 2회 실행해 **멱등성과 note 무손실**을 확인했다.

##### 스크립트가 문구를 3중으로 중복 삽입한 사고

이번 갱신에서 `add-national-screening.mjs`를 돌렸더니 서울 3곳의 국가검진 문구가 **3번씩 반복 삽입**됐다. 원인과 교훈:

- **원인.** 기존 제거 패턴이 `명단에는 "..."으로 올라 있다.`라는 **특정 표현**을 기대했는데, 이번 문구는 `...단독 표기되어 있고 정확히 일치한다`, `...올라 있어 법인명(...)까지` 처럼 표현이 달랐다. 제거에 실패한 채 새 문구가 덧붙어 중복됐다(스크립트를 두 번 돌려 3개가 됐다).
- **고친 방법.** 문구 전문을 나열하는 대신, 여는 문장 뒤에 이어지는 부연 문장을 **시작 단어**(`명단에는` / `명단에 있는` / `공식 홈페이지` / `최초 등록 시` / `법인명` / `정부가`)로 잡아 반복 매칭하도록 일반화했다. **여기 없는 시작 단어로 새 문장을 쓰면 다시 중복되므로, 문구를 새로 만들 때는 이 목록을 먼저 확인한다.**
- **검증 방법도 틀렸었다.** 처음에는 문장을 `Set`으로 중복 제거한 뒤 비교해서 "멱등성 차이 없음"이라는 잘못된 결과를 얻었다. **중복 삽입을 잡으려면 중복을 제거하지 말고 원문 그대로 비교하거나 문구 등장 횟수를 세야 한다.** 지금은 ① 문구 등장 횟수 ② note 원문 완전 일치 ③ 실행 전 문장이 모두 남아 있는지, 세 가지로 검증한다.

- **OSM의 도로·법정동 표기가 공식 주소와 다를 수 있다.** 안동병원은 역지오코딩으로 `amenity=hospital` 노드('안동병원')임을 확인했지만 OSM은 도로·동을 `경북대로·옥동(36663)`으로 적어 두어 공식 주소 `앙실로 11 수상동(36743)`과 다르다. 6번 규칙대로 `address`는 공식 표기를 그대로 두고 불일치만 `note`에 남겼다(부천세종병원과 같은 처리).
- **폼의 입력 제약은 대기 기간 근거가 아니다.** 성가롤로병원 예약 폼은 1차 희망일을 15일 이후, 2차 30일 이후, 3차 45일 이후로만 고를 수 있다. 그럴듯해 보이지만 병원이 공지한 범위가 아니라 **폼 제약일 뿐이므로 `waitingPeriod`에 넣지 않고** `note`에만 적었다.
- **가격을 아예 공개하지 않는 병원이 있다.** 제주한라병원은 "검진비용은 병원으로 문의 부탁드립니다"라고만 안내한다(공개된 것은 진정 내시경 추가비용뿐). 동수원병원·안동병원·전주예수병원·창원파티마병원도 가격이 없어 `priceRange`를 비우고 "검진 가격 정보 확인 필요"를 남겼다.
- **행정구역 개편이 병원 홈페이지에 이미 반영돼 있었다.** 성가롤로병원 푸터는 `전남광주통합특별시 순천시 순광로 221`로 새 표기를 쓰는데, **같은 사이트의 '찾아오시는길' 본문에는 옛 표기 `전라남도 순천시`가 남아 있다.** 한 사이트 안에서도 표기가 엇갈리므로 `address`는 푸터의 새 표기를 따르고 그 사실을 `note`에 적었다. Nominatim도 `전남광주통합특별시`를 인식했다(2026-08-20 확인).
- **아산사회복지재단 계열은 명단 표기가 제각각이다.** 서울·정읍·보성·보령아산병원은 `아산사회복지재단`이 앞에 붙는데 **강릉아산병원만 법인명 없이 단독**으로 올라 있다. 계열 병원이라고 표기가 같을 것이라 가정하면 안 된다.

#### 후보를 뽑은 방법

1. **CSV의 지역 정렬을 이용했다.** `국민건강보험공단_검진기관검진유형내역` CSV는 순번이 지역별로 묶여 있다. 이미 등록된 대전 병원들의 순번(대전한국병원 14743 ~ 건양대병원 15205)으로 **대전 구간을 특정**한 뒤 그 범위에서 `병원`으로 끝나는 기관만 추려 검진 유형 개수로 정렬했다. CSV에 주소 컬럼이 없어도 이 방법으로 지역 필터를 대신할 수 있다.

- **공공기관이 운영하는 종합병원도 `일반종합병원`이다.** 대전보훈병원(한국보훈복지의료공단)과 근로복지공단 대전병원은 재단·의료법인이 아니라 공공기관 직영이지만, `category`의 기준은 13번 항목대로 **"대학 부속병원인가"** 이므로 일반종합병원으로 넣었다. 두 곳 모두 보훈대상자·산재근로자 전용이 아니라 일반인도 이용할 수 있다.
- **전화번호 표기 오류가 또 나왔다.** 근로복지공단 대전병원 직업환경의학과 페이지는 문의 번호를 `042-6705-191`로 적어 두었는데, 자릿수를 맞추면 **042-670-5191**이고 대표번호 042-670-5114와 같은 670 국번이며 외부 병원정보와도 일치한다. 동수원병원(`031)2100-287`)에 이어 두 번째 사례다.
- **메뉴는 있는데 내용이 비어 있는 경우가 있다.** 대전보훈병원의 개인 종합검진에 해당하는 '추가선택검진' 페이지는 **"콘텐츠 준비 중입니다"** 상태라 프로그램·가격·소요시간을 확인할 수 없었다. 홈페이지에 공개된 검진은 국가검진과 채용검진뿐이어서 관련 필드를 비우고 사유를 `note`에 남겼다.

##### 지역 완결성에 대한 소견

위 3곳을 넣으면서 **대전은 종합병원급 이상 11곳 중 10곳이 등록**됐다. 나머지 1곳은 국군대전병원으로 일반 이용 대상이 아니므로, **실질적으로 대전은 전수 등록됐다고 본다.** 다만 다음 두 가지는 한계로 남는다.

- 종별 판단의 1차 근거를 위키백과 목록에 의존했다. 대전광역시청의 '병원급 이상 의료기관 현황'은 심평원 검색으로 연결만 하고 목록 파일을 직접 주지 않으며, 공공데이터포털의 '대전광역시 종합병원 현황' 파일도 받지 못했다. **종별이 바뀌거나(병원↔종합병원 승격·강등) 새로 개원하면 이 목록은 곧 낡는다.**
- 둔산병원처럼 **종별은 병원급이지만 종합검진센터를 제대로 운영하는 곳**은 이번 기준에서 빠졌다. 사용자 입장에서는 유용한 선택지일 수 있으므로, `tier`에 `"병원"`을 허용할지는 별도 판단이 필요하다(타입에는 이미 `병원`·`의원`이 정의돼 있다).

#### 동의병원 — 제외로 결정 — **폐지된 판단(2026-08-22)**

> ⚠️ **[폐지된 판단 — 히스토리 보존]** 아래 내용은 `category` 필드가 있던 시절의 판단 기록입니다. **2026-08-22에 `category` 필드가 폐지되어 결론 자체는 더 이상 데이터에 반영되지 않습니다**([28번 항목](#28-category-필드-폐지--tier-단일-분류로-전환-2026-08-22)). 어떤 근거로 판단이 갈렸는지를 남겨 두기 위해 삭제하지 않고 그대로 둡니다.

19번에서 보류했던 동의병원은 **제외**한다. 근거는 아래와 같다.

- 공식 홈페이지 소개가 운영 주체를 **학교법인 동의학원**으로 밝히고 있고, 동의의료원은 **동의대학교 산하 기관**으로 설명된다.
- 같은 의료원 안에 **동의대학교부속한방병원**이 함께 있어 대학 부속 관계가 명시적이다.
- 공단 검진기관 명단 표기도 `학교법인)동의병원`으로 학교법인임을 드러낸다.

즉 **대학을 운영하는 바로 그 학교법인이 직접 운영하는 병원**이므로, 학교법인 을지학원→대전을지대학교병원, 학교법인 건양교육재단→건양대학교병원과 같은 구조다. 나중에 넣는다면 `category`는 `"일반종합병원"`이 아니라 `"대학병원"`이어야 한다.

**대동병원과 갈리는 지점:** 대동병원도 학교법인(화봉학원)이 운영하지만, 같은 법인이 운영하는 대동대학교의 **부속병원이 아니라 자매기관**이고 병원 이름에도 대학이 들어가지 않는다. 그래서 대동병원은 일반종합병원을 유지했다. **판단 기준은 "학교법인이 운영하는가"가 아니라 "그 대학의 부속병원인가"다.**

> 이번에 대동병원의 `affiliation`을 **`학교법인 대동병원` → `학교법인 화봉학원`으로 정정**했다. 19번 등록 당시 홈페이지 검진센터 페이지의 표기를 그대로 옮겼는데, 실제 법인명은 화봉학원이었다.

- **인천 행정체제 개편이 병원마다 반영 속도가 다르다.** 인천광역시의료원·인천기독병원·검단탑병원·온누리병원은 이미 새 자치구명(제물포구·검단구)을 쓰는데, 뉴성민병원은 아직 옛 `서구`를 쓴다. 9번 규칙대로 `address`는 공식 표기를 그대로 두고 `region.sigungu`만 새 체계로 맞췄다(석남동은 아라뱃길 남측이라 검단구가 아닌 **서해구**다).

#### 좌표에서 걸린 것

- **`SIDO_BOUNDS`의 인천 범위가 강화군·옹진군을 못 감쌌다.** 비에스종합병원(강화읍)은 `amenity=hospital` 노드로 정확히 잡혔는데도 `maxLat 37.7`에 막혀 저장되지 않았다. 인천은 본토(37.3~37.6) 밖에 강화군(~37.85)과 옹진군 백령도(~37.96/124.7)·덕적도(~37.0/126.1)가 있으므로 **`{ minLat: 36.9, maxLat: 38.0, minLng: 124.5, maxLng: 126.9 }`로 넓혔다.** 9번 규칙이 "`SIDO_BOUNDS`는 타입 에러로 안 걸리니 직접 확인한다"고 적어 둔 그 함정이 다른 방향(범위가 좁아 정상 결과를 버림)으로 나타난 사례다.
- **OSM 등록명 불일치가 다섯 번째로 나왔다.** 현대유비스병원은 OSM에 **"유비스병원"**, 뉴성민병원은 **"성민병원"** 으로 등록돼 있어 정식명으로는 도로만 잡힌다. 온병원·문화병원·센텀병원·강남병원에 이은 사례다.
- **좌표를 비운 병원이 2곳 늘었다(총 7곳).** 인천백병원은 Nominatim에 병원 노드가 없고 `백병원 인천`으로는 같은 이름의 **버스정류장**(백병원(송림패션몰))만 나온다. 인천세종병원도 노드가 없고 `세종병원 인천 계양`으로는 `tourism=artwork`("세종병원 조각품")만 나온다 — **같은 혜원의료재단의 부천세종병원이 "세종병원"으로 잡히는 것과 달리 인천 쪽은 노드 자체가 없다.** 17번 항목대로 `QUERIES`에 등록하지 않아 다음 실행에서 잘못된 좌표가 저장되지 않게 했다.
- OSM의 도로·법정동·우편번호가 공식 주소와 다른 곳(인천광역시의료원은 **자치구까지** 다름, 인천기독병원·나사렛국제병원·부평세림병원은 도로/우편번호가 다름)은 6번 규칙대로 `address`를 그대로 두고 불일치만 `note`에 적었다. 뉴성민병원은 OSM 우편번호가 `47714`(부산 대역)로 적혀 있어 OSM 쪽 오기로 보인다.

#### 스크립트 검증에서 실제로 사고가 났다 — 문장 안 마침표 금지 규칙

15번 항목의 세 가지로 검증했더니 **②(note 원문 완전 일치)가 3회 모두 다른 해시**로 나왔다. 원인은 내가 나은병원 문구에 `luga.co.kr`을 넣은 것이었다.

- 제거 패턴이 `[^.]*\.`로 한 문장씩 끊는데, `luga.co.kr`의 마침표에서 문장이 잘려 **뒷부분(`co.kr)과도 맞아 확정했다.`)이 제거되지 않고 매 실행마다 쌓였다.**
- 16번 항목이 "문장 안에 마침표를 넣지 않는 것도 함께 지켜야 한다"고 적어 둔 바로 그 규칙을 어긴 것이다. **문구에 도메인·소수점·약어를 넣으면 안 된다.**
- 문구를 `병원 공식 홈페이지 도메인이 법인명을 그대로 쓴 luga 도메인이라 교차 확인됐다`로 고치고, 손상된 note를 정정 전 상태로 되돌린 뒤 다시 붙였다.
- 재발을 막으려고 **문구를 넣기 전에 기계적으로 검사**하도록 했다: 여는 문장 뒤 각 문장이 ① 허용된 시작 단어(`명단에는` / `명단에 있는` / `공식 홈페이지` / `최초 등록 시` / `법인명` / `정부가`)로 시작하는지 ② 문장 안에 마침표가 없는지 두 가지를 본다. 이번에는 나은병원 1건만 걸렸다.

##### LifeR 예약 플랫폼 — 부천세종병원 때 못 푼 문제가 그대로 남았다

16번 항목에서 부천세종병원의 `bookingType`을 판별하지 못하게 했던 외부 예약 플랫폼 **LifeR**(`lifer.co.kr`)이 인천에서 3곳(인천사랑·인천세종·인천힘찬) 더 나왔다. 이번에 브라우저로 직접 열어 본 결과를 남긴다.

- **상품 목록과 가격은 브라우저로 읽을 수 있다.** 성별 탭(남성/여성)과 검진 종류 탭(공단/종검)을 눌러야 목록이 채워지고, 각 상품에 검진기간과 본인부담금이 붙어 있다. 세 곳 모두 `priceRange`를 여기서 채웠다.
- **`예약신청하기`는 여전히 `confirm()` 확인창을 거친다.** 확인창을 넘겨야 예약 입력 화면이 나오는데, 그 지점을 넘지 못해 **예약 가능일이 실제로 표시되는지**를 확인할 수 없었다. 8번 규칙대로 세 곳 모두 `bookingUrl`·`bookingType`을 함께 비우고 경위와 URL만 `note`에 남겼다.
- 즉 **LifeR을 쓰는 병원은 현재 방식으로는 `bookingType`을 채울 수 없다.** 이 플랫폼을 쓰는 병원이 계속 나오므로, 판별이 필요하면 확인창을 처리할 수 있는 환경에서 한 번에 정리하는 편이 낫다.

##### 개발 서버 콘솔 오류 (데이터와 무관, 기존 문제)

이번 확인 중 `.next`를 지우고 개발 서버를 새로 띄운 뒤에도 브라우저 콘솔에 **`Error: Map container is already initialized.`** 가 반복 발생하는 것을 확인했다. `components/HospitalMap.tsx`의 `MapContainer` 마운트 시점에서 나며 `NotFoundErrorBoundary`가 잡아 트리를 재생성한다 — React 18 개발 모드의 이중 마운트에서 react-leaflet이 Leaflet 컨테이너를 정리하지 않아 생기는 알려진 문제로 보인다. **화면은 정상이고(전국 마커 91개, 타일 렌더 정상) 데이터 변경과 무관**하지만, 오류 로그가 쌓이면 진짜 문제가 묻히므로 별도로 고칠 대상으로 남긴다.

### 26. `Map container is already initialized.` 콘솔 오류 정리 (2026-08-21)

24번 항목 끝에 "별도로 고칠 대상"으로 남겨둔 개발 서버 콘솔 오류를 확인하고 고쳤다.

#### 프로덕션 빌드에서는 나지 않는다

14번 항목의 경고대로 **개발 서버를 먼저 멈추고**(3000 포트 확인) `.next`를 지운 뒤 `npm run build` → `npm run start -- -p 3001`로 확인했다. 첫 로드와 새로고침 모두 **콘솔 오류 0건**, 지도 컨테이너 1개·마커 107개·타일 정상이었다. 즉 **개발 모드 전용 문제**다.

포트를 3001로 나눠 띄웠지만 **`.next`는 dev와 그대로 공유**하므로, 14번 항목의 "개발 서버를 켠 채 빌드하지 말 것"은 포트를 나눠도 똑같이 적용된다. 확인이 끝나면 `.next`를 지우고 개발 서버를 새로 띄워야 한다.

#### 지금 코드에서는 개발 모드에서도 재현되지 않았다

`.next`를 지우고 개발 서버를 새로 띄운 뒤 다음을 모두 시도했으나 오류가 나오지 않았다. **최초 로드 / 새로고침 반복 / 코드 수정으로 Fast Refresh 재렌더 / 훅을 바꿔 Fast Refresh 재마운트 / 시도 전환 / 검색 / 마커 클릭.** 24번 항목에 적힌 그 오류를 이번 확인에서는 한 번도 보지 못했다(그때 어떤 상태에서 시작됐는지는 알 수 없다).

다만 **원인으로 지목된 동작 자체는 그대로 있다.** 임시 프로브를 넣어 확인한 결과는 이렇다.

| 상황 | 언마운트 시점의 컨테이너 |
| --- | --- |
| StrictMode의 가짜 언마운트(최초 마운트 직후) | 문서에 붙어 있고 `_leaflet_id`가 **남아 있음** = `MapContainer`의 정리 effect가 `map.remove()`를 부르지 않았다 |
| 진짜 언마운트(Fast Refresh 재마운트) | 문서에서 떨어졌고 `_leaflet_id`가 **지워짐** = 정상적으로 정리됐다 |

react-leaflet v4의 `MapContainer`는 지도를 만드는 ref 콜백과 정리 effect가 **최초 렌더의 `context`(=null)를 계속 물고 있다.** 그래서 지도가 만들어진 직후에 정리가 돌면 `map.remove()`가 호출되지 않고, 컨테이너에 Leaflet이 찍어둔 `_leaflet_id`와 지도 인스턴스(이벤트 핸들러·타이머 포함)가 그대로 남는다. 같은 `<div>`에 ref가 다시 붙으면 그 위에 지도를 한 번 더 만들려다 `Map container is already initialized.`로 실패한다.

#### 고친 방식 — `MapCleanup`

`components/HospitalMap.tsx`에 `MapCleanup`을 추가하고 **`MapContainer` 안쪽**에 넣었다. 언마운트 때 남아 있는 지도를 대신 정리한다. 조건이 두 개 붙는다.

- **`MapContainer` 안쪽(자식)에 둔다.** React는 언마운트 정리를 부모 → 자식 순서로 부르므로, 자식에 둬야 `MapContainer` 자신의 정리가 끝난 뒤에 실행된다. 부모에 두면 우리가 먼저 지운 지도를 `MapContainer`가 다시 `remove()`하다 터진다(Leaflet의 `Map.remove()`는 두 번 부르면 이미 지워진 `_mapPane`을 참조해 예외가 난다).
- **컨테이너가 문서에서 떨어져 나간 진짜 언마운트에서만 지운다.** StrictMode의 이중 마운트는 effect만 다시 도는 것이라 컨테이너가 그대로 붙어 있고 ref도 다시 붙지 않는다. 그때 지도를 지우면 다시 만들 사람이 없어 **지도가 빈 화면이 된다.** `container.isConnected`로 가른다.
- `_leaflet_id`가 이미 지워져 있으면(= `MapContainer`가 정상적으로 정리한 경우) 아무것도 하지 않는다.

`requestAnimationFrame`이나 애니메이션 콜백은 쓰지 않는다. 11·12번 항목의 제약(프레임이 그려지지 않는 환경에서도 동작해야 한다)을 그대로 지켰고, `fadeAnimation=false`와 `flyTo` 보정 로직은 건드리지 않았다.

`container._leaflet_id`를 조건 없이 지우는 방식은 쓰지 않았다. StrictMode에서 살아 있는 컨테이너의 표식을 지우면 같은 `<div>` 위에 지도가 두 개 만들어질 수 있다.

### 28. `category` 필드 폐지 — tier 단일 분류로 전환 (2026-08-22)

27번 항목 끝에 **"상급종합병원의 `category`를 다시 봐야 한다 (미결)"** 로 남겨 두었던 문제를, `category` 필드 자체를 **폐지**하는 것으로 정리했다. 이제 병원 분류는 `tier`(상급종합병원/종합병원/병원/의원) 하나로만 한다.

#### 폐지 이유 — 기준이 애매해서 판단이 계속 갈렸다

`category`는 13번 항목에서 **"대학 부속병원인가"** 를 기준으로 삼았는데, 이 기준이 현실의 병원 지배구조와 잘 맞지 않아 **같은 계열 안에서도 판단이 매번 갈렸다.**

| 병원 | 대학과의 관계 | 운영 주체 | 그때의 판단 | 갈린 지점 |
| --- | --- | --- | --- | --- |
| 강릉아산병원 | 울산대 의대 교육협력병원(부속 아님) | 아산사회복지재단 | 일반종합병원 (17번) | 협력이지 부속이 아니라서 |
| 서울아산병원 | 울산대 의대 협력(부속 아님) | 아산사회복지재단 | **미결** (27번) | 같은 기준이면 일반종합병원인데, 통념은 대학병원 |
| 삼성서울병원 · 강북삼성병원 | 성균관대 의대 협력(부속 아님) | 삼성생명공익재단 | **미결** (27번) | 위와 동일 |
| 동의병원 | 동의대 부속한방병원과 함께 동의의료원 구성 | 학교법인 동의학원 | 보류(19번) → 제외(20번) → **대학병원으로 등록**(21번) | 한 병원의 판단이 세 번 뒤집힘 |
| 대동병원 | 대동대학교의 자매기관(부속 아님) | 학교법인 화봉학원 | 일반종합병원 (20번) | 같은 "학교법인 운영"인데 동의병원과 결론이 갈림 |

핵심 문제는 세 가지였다.

1. **"부속"의 법적 정의와 사회적 통념이 어긋난다.** 서울아산·삼성서울은 누구나 대학병원으로 부르지만 법적으로는 부속병원이 아니다. 기준을 곧이곧대로 적용하면 통념과 반대되는 결과가 나오고, 통념을 따르면 기준이 무너진다.
2. **판단에 매번 추가 조사가 필요했다.** 법인 정관·설립 근거까지 확인해야 했고(동의병원은 그러고도 세 번 뒤집혔다), 조사 비용이 분류 하나의 가치보다 컸다.
3. **판단 근거가 외부에 공표되지 않는다.** 우리가 내부적으로 정한 기준이라 사용자가 검증할 수 없고, 새 병원을 넣을 때마다 과거 판례를 뒤져야 했다.

반면 `tier`는 **보건복지부가 3년 주기로 공식 지정·고시하는 객관적 등급**이다. 판단이 필요 없고 외부에서 검증 가능하며, 애초에 이런 문제가 생기지 않는다. `category`가 사용자에게 주던 정보(어느 재단·대학 계열인가)는 이미 `affiliation` 필드가 카드 안 "소속" 텍스트로 더 정확하게 보여주고 있었다.

#### 실제로 바꾼 것

| 대상 | 변경 |
| --- | --- |
| `types/hospital.ts` | `CATEGORY_LIST` 상수, `Category` 타입, `Hospital.category` 필드 제거 |
| `data/hospitals.json` | 119곳 전부에서 `"category"` 줄 제거(다른 필드는 그대로) |
| `components/HospitalCard.tsx` | 보라색 `category` 배지 제거. 배지는 `tier` + `국가검진 지정/미지정`만 남음 |
| `components/TierFilter.tsx` · `lib/hospitals.ts` | **변경 없음.** 원래부터 `tier`만 보고 있었고 `category`를 참조한 적이 없다 |
| `affiliation` | **그대로 유지.** 배지가 아니라 펼친 카드 안 "소속: ○○" 텍스트로 계속 표시된다 |

JSON은 `"category"` 줄이 119곳 모두 **4칸 들여쓰기 단독 줄 + 끝 쉼표** 형태로 균일해서, `JSON.parse`/`stringify` 왕복 없이 **해당 줄만 삭제**했다. 왕복을 돌리면 `region`이 `{ "sido": ..., "sigungu": ... }` 한 줄 압축 형식이라 전부 여러 줄로 풀려 파일 전체가 diff에 잡히고, 15번 항목의 `note` 바이트 단위 검증도 무의미해진다.

#### 과거 판단 기록은 지우지 않았다

13·17·20·21·27번의 `category` 관련 판단은 **삭제하지 않고 그대로 두되**, 각 항목 머리에 `⚠️ [폐지된 판단 — 히스토리 보존]` 안내를 붙였다. 결론은 더 이상 데이터에 반영되지 않지만, **어떤 근거로 판단이 갈렸는지가 이 필드를 폐지한 이유 자체**라서 남겨 두는 편이 낫다.

`data/hospitals.json`에도 두 군데 `category` 문자열이 남아 있는데 **둘 다 그대로 두는 것이 맞다.**

- **동의병원의 `note`** — "category를 '대학병원'으로 넣은 근거는 세 가지다…"로 시작하는 21번 판단 근거가 문장으로 들어 있다. 필드가 아니라 본문이고, 21번 항목과 같은 이유로 히스토리로 남긴다. 이 문장이 참조하는 필드는 이제 없다.
- **부천세종병원·인천세종병원의 `sourceUrl`** — 출처 URL 쿼리스트링의 `&category=2`다. 병원 홈페이지 주소의 일부일 뿐 우리 필드와 무관하므로 건드리면 링크가 깨진다.

#### 앞으로

- **신규 병원 등록 시 `category`를 채우지 않는다.** 타입에서 사라졌으므로 넣으면 `tsc`에서 걸린다.
- 27번에서 미등록으로 남아 있던 **상급종합병원 9곳(서울아산·삼성서울·강북삼성 포함)은 이제 분류 고민 없이 `tier: "상급종합병원"`으로 등록하면 된다.** 27번의 미결 사유가 사라졌다. (실제 등록은 [30번 항목](#30-서울-상급종합병원-10곳-등록-2026-08-23)에서 했고, 집계는 9곳이 아니라 **10곳**이었다.)
- `affiliation`은 계속 채운다(아산사회복지재단, 삼성생명공익재단처럼 운영 주체를 그대로 적는다). 여기엔 "부속인가" 판단이 들어가지 않는다.

#### 검증

`npx tsc --noEmit` 통과, 콘솔 오류 0건. 코드 전체에 `category` 참조 0건.

데이터 무손실을 삭제 전후로 대조했다 — **119곳 개수·id 순서 동일, `category`만 제외하면 모든 필드가 완전 일치(불일치 0건), `note` 문자열 변경 0곳, 좌표 보유 110곳 유지.**

| | 카드 | 마커 |
| --- | --- | --- |
| 전국 | 119 | 110 |
| 서울특별시 | 10 | 10 |

브라우저에서 확인한 것 — 카드 119장에 보라색 `category` 배지 **0개**, tier 배지는 상급종합병원 27 + 종합병원 92로 데이터와 정확히 일치, 본문에 "대학병원"·"일반종합병원" 문자열 **0건**. 등급 필터는 상급종합병원만 선택 시 **27곳**, 종합병원만 선택 시 **92곳**, 해제 시 **119곳**으로 정상 작동하고 병원·의원은 데이터가 없어 비활성 상태를 유지했다.

- **홈페이지에 건강검진 메뉴가 아예 없는 종합병원이 있다.** 중앙보훈병원은 전체메뉴 어디에도 검진 항목이 없고 층별 안내에도 검진센터가 없다(조직도의 건강관리과만 확인). 같은 공단의 대전·부산·대구보훈병원은 모두 건강검진 메뉴가 있어 계열이라고 같을 것이라 가정하면 안 된다. 명단에 공단명까지 일치해 국가검진 지정만 확정하고 프로그램·가격은 비웠다.
- **검진센터가 본원과 다른 건물인 곳이 둘 있었다.** 구로성심병원은 본원(경인로 427)과 검진센터(중앙로10-15)가 떨어져 있고 검진센터는 `gschealthcare.com` 별도 사이트다. 보라매병원은 검진센터가 병원 본관이 아니라 인접한 **전문건설회관 15층**이다. 기쁨병원과 같은 처리로 `note`에 남겼다.
- **온라인 예약이 회원 전용이라 판별을 포기한 사례.** 원자력병원은 "프리미엄 검진 인터넷 예약 신청" 링크가 있으나 열면 `/member/login.do`로 넘어간다. 8번 규칙대로 로그인 경로는 기준으로 삼지 않아 `bookingUrl`·`bookingType`을 비우고 `note`에 남겼다. 반대로 구로성심병원 예약 페이지는 로그인 없이 열리고 "상담원이 직접 전화드립니다"라고 명시해 **예약신청**으로 분류했다.
- **좌표가 병원이 아닌 것에 잡힌 경우가 둘.** 대한병원은 주소로 조회하니 건물이 아니라 **도봉로(도로)**가 잡혔고, 보라매병원은 검진센터 주소로 조회하니 같은 건물의 **"플로렌스 파티하우스"**(대관업체)가 먼저 잡혔다. 둘 다 조회어를 병원명 우선으로 바꿔 다시 받았다. **`display_name`을 눈으로 확인하지 않았으면 그대로 저장될 뻔했다.**
- **대한병원은 OSM 주소가 공식과 다르다.** 다시 받은 좌표는 이름이 정확히 `대한병원`인 노드지만 OSM 도로·동 표기가 **노해로·인수동**으로 공식 표기(**도봉로 301·수유동**)와 다르다. 6번 규칙대로 공식 주소를 그대로 두고 불일치만 `note`에 남겼다(국립경찰병원과 같은 처리).

#### 멱등성 검사가 실제로 잡아낸 실수

**이번에 15번 항목의 멱등성 검사가 처음으로 실패를 잡아냈다.** `add-national-screening.mjs`를 3회 돌린 뒤 파일을 비교했더니 5곳의 `note`에서 문장이 **중복 누적**되고 있었다.

원인은 3번 절차에 적힌 규칙을 어긴 것이었다. 제거 정규식은

```
/\s*국가건강검진 지정기관\([^)]*\)\.(\s*(명단에는|명단에 있는|공식 홈페이지|최초 등록 시|법인명|정부가)[^.]*\.)*/g
```

이라서 **후속 문장이 저 여섯 단어로 시작하고 문장 안에 마침표가 없을 때만** 걷어낸다. 그런데 처음 쓴 문구에 아래처럼 시작 단어를 벗어난 문장이 섞여 있었다.

| 병원 | 잘못 쓴 시작 | 고친 시작 |
| --- | --- | --- |
| 중앙보훈병원·보라매병원 | `명단상 검진유형은…` | 앞 문장(`명단에는 …`)에 합침 |
| 대한병원 | `대한병원은 흔한 이름이지만…` | `법인명이 앞에 붙어 있어…` |
| 구로성심병원 | `공식 검진센터 예약 페이지가…` | `공식 홈페이지 검진센터 예약 페이지가…` |
| 금강아산병원 | `같은 재단의 서울아산병원…` | `명단에 있는 같은 재단의…` |

`명단상`은 `명단에는`과 비슷해 보이지만 정규식이 모르는 단어이고, `공식 검진센터`도 `공식 홈페이지`가 아니다. **한 글자 차이로 제거가 실패하고 재실행 때마다 문장이 쌓인다.**

데이터를 등록 직전 상태로 되돌리고 문구를 고쳐 다시 넣었으며, 같은 실수를 막으려고 등록 스크립트에 **시작 단어와 마침표를 사전 검증하는 가드**를 넣어 규칙을 어기면 등록 자체가 실패하도록 했다.

- **계열로 묶어 추정하면 안 된다는 것이 또 확인됐다.** 같은 아산사회복지재단인데 금강아산병원·강릉아산병원은 일반검진과 암검진을 모두 시행한다. 22번 항목(은성의료재단)의 교훈이 국가검진 쪽에서 반복됐다.

#### 스크립트에서 고친 결함 — 미지정 문구는 가드가 보지 않고 있었다

29번에서 만든 `assertRemovable` 가드는 **`DESIGNATED_SENTENCE_BY_ID`만** 검사한다. 그래서 `NOT_DESIGNATED`와 `UNDETERMINED` 문구는 제거 패턴과 어긋나도 아무도 잡아 주지 않았고, 이번처럼 새 형태를 넣으면 재실행 때마다 조용히 중복 누적될 수 있었다.

- 시작 단어 목록을 늘리는 대신 **문구를 `stripObsolete`에 그대로 통과시켜 빈 문자열이 되는지 보는** `assertStrippable`을 추가하고 세 맵과 기본 문구를 모두 검사한다. 간접 규칙이 아니라 실제 제거 함수를 쓰므로 **앞으로 어떤 형태를 새로 만들어도 여기서 걸린다.**
- 이번에 필요한 새 형태(명단에는 있으나 영유아검진뿐이라 미지정)를 위해 제거 패턴 `/\s*국가건강검진 미지정 — [\s\S]*?시행하지 않는 것으로 확인된다\([^)]*\)\./g`를 함께 넣었다. 앞부분에 괄호가 여럿 들어가므로 **고정된 꼬리까지 비탐욕으로 끊고, 꼬리 괄호 안에는 닫는 괄호를 넣지 않는다.**

### 39. 국가검진 배지를 미지정일 때만 표시 (2026-08-23)

카드의 국가검진 배지를 **`false`(미지정)일 때만** 띄우도록 바꿨다. 초록색 "국가검진 지정기관" 배지는 더 이상 표시하지 않는다.

| 값 | 의미 | 변경 전 배지 | 변경 후 배지 |
| --- | --- | --- | --- |
| `true` | 명단·공지로 지정 확인 | 초록 "국가검진 지정기관" | **없음** |
| `false` | 명단·공지로 미지정 확인 | 주황 "국가검진 미지정" | 주황 "국가검진 미지정"(유지) |
| 없음(`undefined`) | 아직 확인 못 함 | 없음 | 없음(유지) |

이유는 단순하다. **153곳 중 147곳(96퍼센트)이 지정기관**이라 배지가 거의 모든 카드에 붙어 있었고, 거의 항상 뜨는 표시는 카드를 훑을 때 걸러 낼 정보가 되지 못한다. 반대로 미지정 6곳은 사용자가 반드시 알아야 할 예외라서 그대로 둔다.

#### 데이터 판정 규칙은 바뀌지 않았다

이 항목은 **화면 표시 규칙만** 바꾼 것이다. [7번 규칙](#7-nationalscreeningdesignated-국가검진-지정기관-여부)은 그대로 유효하다.

- `nationalScreeningDesignated`는 계속 **`true` / `false` / 없음(미확인)** 세 상태를 구분해 저장한다. 타입도 그대로 `boolean?`이다.
- 값은 여전히 **국민건강보험공단 검진기관 명단 대조**나 **병원 공식 홈페이지 공지** 둘 중 하나로만 정한다. 확인되지 않으면 **값을 넣지 않고 미확인으로 남긴다.**
- **등급으로 추정하지 않고, "대부분 지정기관이니까"라는 다수결로도 추정하지 않는다.** 배지가 사라졌다고 해서 확인 절차를 건너뛰어도 된다는 뜻이 절대 아니다 — 오히려 지정 여부가 화면에 드러나지 않으므로 `note`에 남기는 근거 문구가 유일한 검증 수단이 된다.
- `scripts/add-national-screening.mjs`와 그 문구·가드는 **하나도 건드리지 않았다.** 실행 요약도 계속 `지정 147곳 / 미지정 6곳 / 미확인 0곳`으로 세 갈래를 보여준다.

> **배지가 없다는 것은 "지정이거나 미확인"이라는 뜻이지 "미지정"이라는 뜻이 아니다.** 카드에서 지정 여부를 확정적으로 알 수 있는 것은 주황 배지가 붙은 경우뿐이며, 나머지는 `note`의 근거 문구를 봐야 한다. 이 구분을 `components/HospitalCard.tsx`와 `types/hospital.ts` 주석에도 적어 두었다.

### 41. note 문단 나누기 — 주제가 바뀌는 지점에 줄바꿈 (2026-08-23)

40번에서 문장을 정리했지만 `note`가 여전히 **한 덩어리 문단**이라 연락처·위치·국가검진 근거가 줄바꿈 없이 이어져 읽기 어려웠다. 153곳 전부에 **주제가 바뀌는 지점의 문단 구분만** 넣었다.

| 문단 수 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- |
| 병원 수 | 24 | 60 | 49 | 20 |

#### 줄바꿈이 화면에 반영되지 않고 있었다

`HospitalCard`가 `note`를 `<p>{hospital.note}</p>`로 그냥 렌더링해서 **`white-space` 기본값(normal)이 줄바꿈을 공백으로 접고 있었다.** 데이터에 `\n\n`을 넣어도 화면은 그대로 한 덩어리였다는 뜻이라, 컴포넌트를 함께 고쳤다.

- `<p>`에 **`whitespace-pre-line`**을 붙였다. 줄바꿈은 살리고 연속 공백은 계속 접으므로, JSON 들여쓰기가 화면에 새어 나오지 않는다.
- 가독성을 위해 `leading-relaxed`도 함께 줬다.

#### 스크립트가 문단을 도로 붙이던 문제도 고쳤다

`add-national-screening.mjs`의 `withSentence()`가 국가검진 문구를 **공백 하나로** 이어 붙이고 있었다. 그대로 두면 문단을 나눠 놔도 **이 스크립트를 한 번만 돌리면 국가검진 문구가 앞 문단에 흡수된다.** 빈 줄(`\n\n`)로 붙이도록 바꿔, 재실행해도 문단 구성이 유지되게 했다.

#### 주제 판별 기준

문장 순서와 단어는 그대로 두고, **주제가 바뀌는 지점에만** 문단을 끊었다(순서를 바꾸지 않으므로 같은 주제가 앞뒤로 떨어져 있으면 문단도 떨어진 채로 둔다).

| 주제 | 판별 단서 |
| --- | --- |
| 주소·위치 | OSM, Nominatim, 좌표, 지도 마커, 우편번호, 법정동, 도로명, 주소, 본관·별관·후관 등 건물명, `N층` |
| 연락처 | 번호, 대표전화, 팩스, 내선, ARS, 국번, 직통, 그리고 실제 전화번호 패턴 |
| 예약 방식 | 예약, 온라인, 인터넷, 로그인, 달력, 콜백, 플랫폼, 카카오톡 |
| 국가검진 근거 | `add-national-screening.mjs`가 붙이는 문구 — **항상 마지막 문단** |

- **주제어가 겹치는 문장이 많아 우선순위를 뒀다.** "검진센터 전용 예약 번호(...)"는 예약과 번호를 모두 담고 있는데 연락처로 봐야 한다. 그래서 주소 → 연락처 → 예약 순으로 검사한다.
- **맨 '전화'는 연락처 단서에서 뺐다.** "숙박건진은 전화예약만 가능하다"가 연락처 문단으로 새어 삼성서울병원이 5문단으로 쪼개지는 문제가 있었다. 번호를 가리키는 표현(`대표전화`·`전화번호`)과 숫자 패턴만 잡도록 좁혔다.
- **주제가 불분명한 문장(운영 주체, 검진 프로그램 등)은 앞 문단에 붙인다.** 그러지 않으면 한 문장짜리 문단이 우수수 생긴다.

#### 40번 작업이 남긴 비문 3건을 함께 바로잡았다

이번 점검에서 40번의 일괄 치환이 만든 오류가 드러나 고쳤다. **이번 작업의 원칙(단어를 건드리지 않는다)에서 예외로 둔 유일한 변경이다.**

| 병원 | 잘못된 문장 | 고친 문장 |
| --- | --- | --- |
| 전남대학교병원·조선대학교병원 | 시·군·구는 개편 대상이 아니라 **시·군·구는** 동구 그대로다 | 시·군·구는 개편 대상이 아니라 동구 그대로다 |
| 연세대학교 원주세브란스기독병원 | …전화로 확정하는 **콜백형이라.** | …전화로 확정하는 **콜백형이다.** |

### 42. 칩 클러스터형 카드 시안 — 홍익병원 한 곳에만 적용 (2026-08-23)

카드 디자인을 **칩 클러스터형**으로 바꾸는 안을 전체 적용 전에 **홍익병원 한 곳에서만** 볼 수 있게 만들었다. 나머지 152곳은 기존 `HospitalCard` 그대로다.

#### 구성

| 파일 | 역할 |
| --- | --- |
| `lib/noteChips.ts` | note 문단을 주제별로 나누고 칩을 뽑는 순수 함수(`splitNoteParagraphs`, `deriveChips`) |
| `components/HospitalCardChips.tsx` | 칩 클러스터형 카드 **시안 컴포넌트** |
| `app/page.tsx` | `CHIP_PREVIEW_IDS`에 든 id만 시안 컴포넌트로 렌더 |

`HospitalCard.tsx`는 **한 줄도 건드리지 않았다.** 전체 적용이 결정되면 시안을 본체로 합치고 스위치와 시안 파일을 지우면 된다.

#### 칩은 note에서 자동으로 뽑는다

41번에서 note에 넣어 둔 **주제별 문단 구분을 그대로 재사용**한다. 문단을 다시 계산하지 않고 `\n\n`으로 끊은 뒤 같은 기준(주소 → 연락처 → 예약 → 국가검진)으로 주제를 붙인다.

| 칩 | 근거 |
| --- | --- |
| 전화번호 | `phone` 필드 + 연락처 문단 머리에서 창구 이름 추출("건강증진센터 대표번호…" → `건강증진센터`) |
| 검진센터 위치 | 주소 문단에서 건물·층 추출(`별관 1층`) + `본원과 다른 건물` 문구 감지 |
| 온라인 예약 | `bookingUrl`·`bookingType` 필드 |
| 소요시간·식사 | `duration`·`mealProvided` 필드(있을 때만) |
| 국가검진 | `nationalScreeningDesignated` |

**필드가 있는 것은 필드를 1차 근거로 쓰고, note에서는 필드에 없는 것(검진센터 위치, 창구 이름)만 보충한다.** note 파싱만으로 만들면 표현이 조금만 달라져도 칩이 사라지기 때문이다.

색은 세 가지다 — 기본(회색), **국가검진 지정(초록)**, 주의(주황: 미지정, 본원과 다른 건물).

#### 홍익병원에서 실제로 나온 칩

```
홍익병원 [종합병원]
서울특별시 양천구
( 건강증진센터 02-2600-0591 ) ( 검진센터 별관 1층(본원과 다른 건물) ) ( 전화·방문 예약만 ) ( 국가검진 지정기관 )
확인일 2026-08-23   출처 보기 ↗                                          자세히 보기 ▾
```

- 전화 칩은 `tel:` 링크이고, 카드 클릭(지도 이동)으로 전파되지 않도록 `stopPropagation`을 건다.
- **국가검진 지정 칩이 초록으로 살아났다.** 39번에서 헤더 배지를 없앤 뒤로 지정 여부가 note 안에만 있었는데, 칩 요약에서는 다시 한눈에 보인다(카드가 길어지지 않으면서).
- "자세히 보기"를 펼치면 예약 방식 한 줄, 부가 필드, **41번의 note 문단 3개**가 그대로 나온다 — 요약은 칩, 근거는 펼치기 뒤라는 구조다.

#### 아직 정하지 않은 것

- 전체 적용 여부. 적용한다면 **note가 짧은 병원에서는 칩이 2~3개뿐이라 헐거워 보일 수 있다** — 칩이 일정 개수 미만이면 기존 레이아웃으로 떨어뜨리는 규칙이 필요할지 판단이 필요하다.
- 지금 시안은 헤더에서 전화번호를 빼고 칩으로 옮겼다. 목록을 훑을 때 전화번호가 한 줄 아래로 내려간 셈이라, 실제 사용 흐름에서 불편한지 확인이 필요하다.
